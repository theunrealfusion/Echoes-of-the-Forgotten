## 4. Prompt Quality Defect Analysis & 5/5 Revised Prompts

### Root Causes of Generation Failures in Naive Prompts
Analysis of early pipeline templates (`pipeline/asset_generator.py`) revealed five critical failure patterns in text-to-3D diffusion models:
1. **Generic Slug Contamination**: Inserting raw programming identifiers (`sunken_library`, `deep_forge`) into prompts confuses NLP tokenizers, leading to messy, ambiguous outputs.
2. **Pedestal & Diorama Artifacts**: Without explicit isolation directives, 3D generation algorithms routinely bake decorative plinths, ground slabs, or diorama boxes onto the model, ruining runtime collision boxes.
3. **Scale Incoherence**: Small handheld artifacts inheriting room-scale descriptions (e.g. "vast cavern ceilings", "sweeping platforms") generate tiny miniature buildings instead of clean props.
4. **Thematic Contradiction**: Hardcoded generic phrases like "coral or fungal growth" cause the model to generate underwater marine coral inside an underground volcanic magma forge (`deep_forge`) or aerial cloud cities (`sky_nomads`).
5. **NPC Deformation & Ground Plates**: Character prompts lacking explicit T-pose instructions generate models with baked ground shadows, asymmetric limbs, or dynamic poses that fail auto-rigging.

## 5. Mandatory Generation Best Practices & Negative Prompts

When executing batch runs via `pipeline/batch_runner.py` or the Tripo V3 API, every call must enforce these parameters:

### Negative Prompt Template
```
pedestal, base, display stand, plinth, ground plate, slice, cut off, cropped, floating debris, room interior, background geometry, low-poly wireframe, blurry textures, distorted face, asymmetric limbs, text, watermark, signature
```

### Tripo V3 Task Configuration
- **Model Format**: `.glb`
- **PBR**: `True` (Roughness, Metalness, Normal maps)
- **Texture Quality**: `high`
- **Quad Retopology**: `target_faces=5000` (environment buildings), `target_faces=2500` (handheld relics), `target_faces=5000` (characters)
- **Orientation**: Centered on coordinate origin [0,0,0], Z-up / Y-up normalized for Three.js import
